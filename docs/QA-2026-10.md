# QA baseline (October 2026)

Work in progress. All checks below were performed by an automated assistant in
isolated synthetic homes, not by a human. No real credentials, provider logins,
model calls, account changes or existing user configuration were used.

## Reproduced and fixed locally

- Profile activation deleted an unmanaged configuration when an existing default
  profile prevented migration. Activation now refuses that collision, validates
  directory targets, and rolls back failed link replacement. Migration also
  restores the original directory if link creation fails.
- Untrusted-origin form POSTs could change configuration even when CORS did not
  expose the response. Request-origin and loopback Host enforcement now run before
  body parsing and routes. Unrelated Vercel tenants and deceptive LAN hostnames
  are no longer trusted. Exact hosted Studio origins remain supported.
- A newly created `.ts` plugin could not be read back by its explicit filename.
  Lookup now includes the exact supported filename.
- Backups discarded plugin extensions and restored TypeScript as JavaScript.
  Local and cloud backup payloads now retain an optional `.js`/`.ts` extension;
  legacy entries without an extension still restore as `.js`. Malformed resource
  content or extensions are rejected before any restore writes.
- The server could select ports beyond the ten ports the client searches, and
  could retry permission errors indefinitely. Startup binds the actual loopback
  socket within 1920–1929 and only retries occupied ports.
- Profile switching did not refresh shared client configuration. A switch now
  refreshes shared data, and stale earlier refresh results cannot overwrite it.
- The provider test file depended on undeclared Vitest while the package was
  CommonJS. It now uses the existing native Node test runner with isolated cleanup.
- Stale DOMPurify/PostCSS overrides produced dependency audit findings. Updated
  overrides resolve to 3.4.17 and 8.5.31, with reproducible lockfiles.

- Command rename previously deleted the original before saving the new name.
  It now saves first, preserving the source on write failure and retaining both
  copies on removal failure. Whitespace-only renames no longer delete the file.
- Frontend development port discovery is bounded to 1080–1089, binds loopback,
  and reports non-occupancy errors instead of retrying indefinitely.
- Editor navigation ignores stale file responses and stale load errors.
- Error presentation validates unknown backend error values before passing them
  to translated UI messages.

- Profile mutations are serialized so rapid Enter presses and overlapping switches
  cannot start concurrent writes.
- Non-object main configurations and malformed backup objects are rejected before
  writes; an HTTP regression reproduced the original array-config corruption.

- Restored the missing agent-delete confirmation dialog; cancellation never calls
  the delete API and confirmation targets the selected agent.
- Raw config drafts survive background refresh and edits made while saving.
- Connection-state changes no longer restart initial refreshes and race user work.

### Additional v2 QA findings

- Actual browser reproduction: edit native agent ordered permissions, save, then
  toggle MCP on another page. The old shared config snapshot overwrote the new
  permission rule. MCP mutation handlers now fetch the current configuration
  before applying their edit; a regression test verifies unrelated edits survive.
- Native agent JSON entries were mislabeled Built-in; treat `json-config` as JSON.
- V2 uses `session_message` and `session_v2`. Usage now reads either or both table
  generations, avoids duplicate message IDs, and reports database failures rather
  than silently replacing failures with a zero-spending report. Synthetic SQL
  fixtures verify native/legacy totals and the failure response.

### Final browser retest of changed flows

- Repeated native agent permission edit → MCP toggle → Raw Config on the fixed
  production build. Both ordered rules, explicit model object, MCP global timeout
  and `codemode` survived. The previous build lost the second permission rule.
- Separate v2 CLI tab: invalid JSON was rejected with the draft retained; valid
  synthetic CLI settings saved. Native auth page showed its read-only explanation
  and no misleading legacy login/pool controls.
- Audits report zero known vulnerabilities for backend production dependencies
  and frontend dependency tree at the time of this check.
- Legacy `/api/auth` also returned the raw stored auth object alongside status.
  It now returns status metadata only; a synthetic-key regression asserts that
  secrets are absent while provider login status remains available.
